================================================================================
1️⃣  رابط ملف الصوت (Audio URL)
================================================================================

الوصف:
-------
بعد ما الطالب يسجل صوته ويرفعه على السيرفر، الـ Backend يحفظ الملف على 
Cloud Storage (OVH/S3) ويحصل على رابط للملف.

المطلوب إرساله:
----------------
✅ audioUrl: "https://storage.yutlaquran.com/recitations/user-123/rec-456.mp3"

مثال:
------
{
  "audioUrl": "https://cdn.yutlaquran.com/recitations/user-15/recitation-789.mp3"
}


================================================================================
2️⃣  معلومات الآيات المطلوب تقييمها
================================================================================

الوصف:
-------
الـ AI محتاج يعرف الطالب بيسمع إيه علشان يقارن صوته بالنص الصحيح.

المطلوب إرساله:
----------------
✅ surahNumber: رقم السورة (1-114)
✅ surahName: اسم السورة بالعربي (الفاتحة، البقرة، ...)
✅ fromAyah: رقم الآية الأولى
✅ toAyah: رقم الآية الأخيرة
✅ ayahsText: نص الآيات الصحيح (اختياري - الـ AI ممكن يجيبه بنفسه)

مثال:
------
{
  "surahNumber": 1,
  "surahName": "الفاتحة",
  "fromAyah": 1,
  "toAyah": 7,
  "ayahsText": [
    "بِسْمِ اللَّهِ الرَّحْمَٰنِ الرَّحِيمِ",
    "الْحَمْدُ لِلَّهِ رَبِّ الْعَالَمِينَ",
    "الرَّحْمَٰنِ الرَّحِيمِ",
    "مَالِكِ يَوْمِ الدِّينِ",
    "إِيَّاكَ نَعْبُدُ وَإِيَّاكَ نَسْتَعِينُ",
    "اهْدِنَا الصِّرَاطَ الْمُسْتَقِيمَ",
    "صِرَاطَ الَّذِينَ أَنْعَمْتَ عَلَيْهِمْ غَيْرِ الْمَغْضُوبِ عَلَيْهِمْ وَلَا الضَّالِّينَ"
  ]
}

================================================================================
1️⃣  نسبة الدقة الإجمالية (Overall Accuracy)
================================================================================

الوصف:
-------
نسبة مئوية توضح مدى دقة تلاوة الطالب بشكل عام.

المتوقع استقباله:
------------------
✅ overallAccuracy: رقم من 0 إلى 100
✅ overallScore: رقم من 0 إلى 100 (نفس الشيء)

مثال:
------
{
  "overallAccuracy": 85.5,
  "overallScore": 85.5
}


================================================================================
2️⃣  عدد الكلمات الصحيحة والخاطئة
================================================================================

الوصف:
-------
إحصائيات عن عدد الكلمات اللي الطالب قرأها صح والغلط.

المتوقع استقباله:
------------------
✅ totalWords: إجمالي عدد الكلمات
✅ correctWords: عدد الكلمات الصحيحة
✅ incorrectWords: عدد الكلمات الخاطئة

مثال:
------
{
  "totalWords": 50,
  "correctWords": 45,
  "incorrectWords": 5
}


================================================================================
3️⃣  تفاصيل كل كلمة (Word-level Details)
================================================================================

الوصف:
-------
معلومات مفصلة عن كل كلمة في التلاوة (صح/غلط/نوع الخطأ).

المتوقع استقباله:
------------------
✅ words: مصفوفة من الكلمات
   - wordText: نص الكلمة
   - isCorrect: صح ولا غلط (true/false)
   - confidence: نسبة الثقة (0-100)
   - errorType: نوع الخطأ (إذا موجود)
   - timestamp: الوقت في الصوت (ثانية)

مثال:
------
{
  "words": [
    {
      "wordText": "بِسْمِ",
      "isCorrect": true,
      "confidence": 95.5,
      "errorType": null,
      "timestamp": { "start": 0.0, "end": 0.5 }
    },
    {
      "wordText": "اللَّهِ",
      "isCorrect": false,
      "confidence": 65.0,
      "errorType": "pronunciation",
      "timestamp": { "start": 0.5, "end": 1.2 }
    },
    {
      "wordText": "الرَّحْمَٰنِ",
      "isCorrect": true,
      "confidence": 92.0,
      "errorType": null,
      "timestamp": { "start": 1.2, "end": 2.0 }
    }
  ]
}

4️⃣  تفاصيل الأخطاء (Error Categories)
================================================================================

الوصف:
-------
تصنيف الأخطاء حسب النوع (حفظ، تجويد، مخارج، مدود، إلخ).

المتوقع استقباله:
------------------
✅ errors: مصفوفة من الأخطاء
   - errorType: نوع الخطأ
   - count: عدد الأخطاء من هذا النوع
   - details: تفاصيل إضافية

أنواع الأخطاء المتوقعة:
-------------------------
- memorization: أخطاء حفظ (كلمة ناقصة، كلمة زيادة، ترتيب خاطئ)
- tajweed: أخطاء تجويد (غنة، قلقلة، إدغام، إخفاء)
- pronunciation: أخطاء مخارج الحروف
- madd: أخطاء المدود (طويل، قصير)
- harakat: أخطاء الحركات (فتحة، ضمة، كسرة)
- sifaat: أخطاء صفات الحروف

مثال:
------
{
  "errors": [
    {
      "errorType": "tajweed",
      "count": 2,
      "details": [
        {
          "wordText": "الرَّحِيمِ",
          "description": "غنة ناقصة",
          "severity": "medium",
          "timestamp": { "start": 2.0, "end": 2.8 }
        },
        {
          "wordText": "نَعْبُدُ",
          "description": "إدغام غير واضح",
          "severity": "low",
          "timestamp": { "start": 5.5, "end": 6.2 }
        }
      ]
    },
    {
      "errorType": "pronunciation",
      "count": 1,
      "details": [
        {
          "wordText": "الصِّرَاطَ",
          "description": "حرف الصاد غير واضح",
          "severity": "high",
          "timestamp": { "start": 8.0, "end": 8.7 }
        }
      ]
    }
  ]
}

الخطوات بالتفصيل:
================================================================================

1️⃣  الطالب يسجل صوته في التطبيق (Unity/Unreal)
   └─> التطبيق يرفع الملف على Backend

2️⃣  الـ Backend يستقبل الملف
   └─> POST /recitations/upload
   └─> يرفع الملف على Cloud Storage (OVH/S3)
   └─> يحصل على رابط: https://storage.yutlaquran.com/recitations/...
   └─> يحفظ البيانات في جدول recitations
   └─> يُرجع للتطبيق: recitationId

3️⃣  الـ Backend يُرسل البيانات لمهندس الـ AI
   └─> POST https://ai-service.yutlaquran.com/api/evaluate
   └─> Body:
       {
         "audioUrl": "...",
         "surahNumber": 1,
         "fromAyah": 1,
         "toAyah": 7,
         ...
       }

4️⃣  مهندس الـ AI يُعالج الصوت
   └─> Speech-to-Text
   └─> مقارنة مع النص الصحيح
   └─> تحديد الأخطاء
   └─> حساب النسب

5️⃣  مهندس الـ AI يُرجع النتيجة
   └─> Response JSON كامل بكل التفاصيل

6️⃣  الـ Backend يستقبل النتيجة
   └─> يحفظها في جدول recitations
       - evaluation_score
       - evaluation_data (JSON)
   └─> يُحدث status: completed

7️⃣  التطبيق يطلب النتيجة من Backend
   └─> GET /recitations/:id
   └─> يعرضها للطالب

1. تنسيق JSON
   -----------
   ✅ تأكد إن مهندس الـ AI يرجع Response بنفس البنية المتفق عليها
   ✅ استخدم نفس أسماء الحقول (overallScore, words, errors, إلخ)

2. معالجة الأخطاء
   ---------------
   ✅ لو الـ AI فشل في المعالجة، يرجع:
      {
        "status": "error",
        "message": "سبب الخطأ"
      }
   
   ✅ الـ Backend يحدّث status إلى failed

3. المدة الزمنية
   -------------
   ✅ لو المعالجة هتاخد وقت طويل (> 10 ثواني):
      - استخدم Async Processing
      - الـ AI يرجع: { "status": "processing", "jobId": "..." }
      - Backend يستعلم عن النتيجة لاحقاً

4. الأمان
   -------
   ✅ استخدم API Key أو JWT Token للتأكد من الهوية
   ✅ تأكد إن الـ AI يقدر يوصل للملفات على Cloud Storage

5. حجم الملف
   -----------
   ✅ الحد الأقصى: 100 MB
   ✅ لو أكبر، الـ Backend يرفض قبل ما يرسل للـ AI

6. التخزين
   ---------
   ✅ evaluation_data يتخزن كـ JSON كامل
   ✅ evaluation_score يتخزن كرقم عشري

Endpoint 1: تقييم التلاوة
--------------------------
POST /api/evaluate

Request:
{
  "audioUrl": "string",
  "surahNumber": "number",
  "fromAyah": "number",
  "toAyah": "number",
  "ayahsText": ["string"],
  "userId": "number",
  "recitationId": "number"
}

Response:
{
  "status": "success|error|processing",
  "data": { ... } // كل التفاصيل اللي فوق
}


Endpoint 2: استعلام عن نتيجة (لو Async)
----------------------------------------
GET /api/evaluate/:jobId

Response:
{
  "status": "success|error|processing",
  "data": { ... }
}

ما تُرسله لمهندس الـ AI:
===========================
1. رابط الملف الصوتي (audioUrl)
2. معلومات السورة والآيات (surahNumber, fromAyah, toAyah)
3. نص الآيات (اختياري)
4. معلومات إضافية (userId, recitationId)


ما تستقبله من مهندس الـ AI:
==============================
1. نسبة الدقة الإجمالية (overallScore)
2. عدد الكلمات الصحيحة والخاطئة
3. تفاصيل كل كلمة (صح/غلط/وقت)
4. تصنيف الأخطاء (تجويد، مخارج، حفظ، إلخ)
5. توصيات لتحسين التلاوة
6. النص المكتشف (اختياري)


الحقول في قاعدة البيانات:
============================
✅ evaluation_score  ← نسبة الدقة
✅ evaluation_data   ← كل Response الـ AI (JSON كامل)
